# 화면 생김새 개선 점검 항목

화면을 전문가가 만든 수준으로 다듬을 때 보는 점검 항목의 정본입니다. 항목마다 **무엇을 보나 · 예 · 지시 문장 예**를 적었습니다. 지시 문장은 화면을 그리는 에이전트에게 그대로 줄 수 있는 모양입니다.

이 목록은 aikung 프로젝트에서 사용자에게 보여 주고 「전부 적용」으로 효과를 본 것입니다. 항목 코드(A1·B2 같은 것)는 지시서와 완료 보고에서 그대로 씁니다.

## 1. 언제 쓰나

- 목업의 화면이 「동작은 하지만 평범해 보일 때」 — 위계가 없고, 간격이 들쭉날쭉하고, 글자 크기가 제각각일 때
- 화면을 개선하라는 지시서를 쓸 때 — 아래 항목 코드 중 고칠 것을 골라 지시서에 적습니다
- 개선이 끝난 화면을 점검할 때 — 항목 코드별로 지켜졌는지 봅니다

**지시서를 쓰는 메인이 이 문서를 읽고, 그 화면에 닿는 항목만 걸러서 지시서에 넣습니다.** 그리는 에이전트에게 이 문서를 통째로 읽히지 않습니다.

## 2. 작업 순서와 확인 폭

1. **핵심 화면 하나의 데스크톱(1440)을 먼저 완성합니다.**
2. **그 화면에서 글자·간격·색 규칙표를 뽑아** 공통 스타일에 고정합니다.
3. **같은 화면을 폰(390)으로 접습니다.**
4. **규칙이 맞으면 나머지 화면 전체에 적용합니다.**

**규칙표를 먼저 만들게 하고, 그다음 그리게 합니다.** 화면을 그린 뒤에 규칙을 뽑으면 이미 어긋난 값을 규칙으로 굳히게 됩니다.

확인 폭은 1440 · 1024 · 768 · 390입니다. **1440과 390만 그리고**, 1024와 768은 「어느 폭에서 무엇이 접히는지」 메모로만 남깁니다.

## 3. A 시선과 위계

**A1 화면마다 주인공 하나**
- 무엇을 보나 — 화면을 3초 봤을 때 먼저 눈에 들어오는 것이 그 화면의 목적과 같은가
- 예 — 목록 화면인데 제목 배너가 가장 커서 목록이 묻힘
- 지시 — 「1순위 ○○, 2순위 ○○, 3순위 ○○. 1순위만 가장 크고 진하게, 나머지는 크기·굵기·명도로 한 단계씩 낮춰라」

**A2 주 버튼은 화면당 하나**
- 무엇을 보나 — 강조색으로 꽉 찬 버튼이 둘 이상 있는가
- 예 — 「저장」과 「공유」가 둘 다 꽉 찬 강조색
- 지시 — 「강조색 꽉 찬 버튼은 화면당 하나, 나머지는 테두리 버튼이나 글자 버튼으로」

**A3 덜어내기**
- 무엇을 보나 — 같은 정보가 두 번 나오는가, 지금 판단에 필요 없는 정보가 있는가
- 예 — 목록 한 줄에 정보 덩어리가 일곱 개
- 지시 — 「목록 한 줄 정보는 최대 ○개, 뺀 것은 상세 화면으로」

## 4. B 글자

**B1 크기 단계 제한**
- 무엇을 보나 — 쓰는 글자 크기가 다섯 안팎으로 정해져 있는가
- 예 — 13·15·17·19 같은 어중간한 크기가 섞임
- 지시 — 「30·24·18·16·14 다섯 단계만 쓴다. 단계마다 쓰는 자리를 표로 먼저 만든다」

**B2 줄 간격과 자간**
- 무엇을 보나 — 줄 간격이 글 종류에 맞는가
- 예 — 제목 1.3, 본문 1.6, 24px 이상 제목은 자간 -0.02em
- 지시 — 「제목 줄 간격 1.3, 본문 1.6, 24px 이상 제목 자간 -0.02em」

**B3 한글 줄바꿈**
- 무엇을 보나 — 낱말 중간에서 줄이 끊기는가, 두 줄 제목의 길이가 크게 다른가
- 예 — 「추천 여행 코-스」처럼 낱말 가운데서 끊김
- 지시 — 「낱말 단위로 줄을 바꾼다(`word-break: keep-all`). 두 줄 제목은 두 줄 길이가 비슷하게」

## 5. C 간격과 정렬

**C1 간격 단위**
- 무엇을 보나 — 간격이 4의 배수인가
- 예 — 4·8·12·16·24·32·48·64만 쓰는데 13px, 18px이 끼어 있음
- 지시 — 「간격은 4·8·12·16·24·32·48·64만 쓴다」

**C2 근접성(가까운 것끼리 한 묶음으로 보이는 현상)**
- 무엇을 보나 — 같은 묶음 안의 간격이 묶음 사이 간격보다 충분히 작은가
- 예 — 제목과 설명 사이가 카드와 카드 사이만큼 벌어져 한 묶음으로 안 보임
- 지시 — 「묶음 안 간격은 묶음 사이 간격의 절반 이하로」

**C3 정렬 기준선**
- 무엇을 보나 — 모든 요소의 왼쪽 끝이 같은 선에 맞는가
- 예 — 섹션마다 왼쪽 시작 위치가 조금씩 다름
- 지시 — 「12단 격자를 쓰고 모든 요소의 왼쪽 끝을 격자 선에 맞춘다. 본문 최대 폭을 정한다」

**C4 읽는 폭**
- 무엇을 보나 — 긴 글 한 줄이 너무 길지 않은가
- 예 — 한 줄이 80자를 넘어 눈이 줄을 놓침
- 지시 — 「긴 글은 한 줄 40~45자(약 680px) 이하로」

## 6. D 색

**D1 색 쓰는 비율(60-30-10)**
- 무엇을 보나 — 강조색이 누르는 것과 선택된 것에만 쓰이는가
- 예 — 장식 선과 제목 글자에도 강조색을 칠해서 어디를 눌러야 하는지 흐려짐
- 지시 — 「강조색은 누르는 것·선택된 것에만 쓰고 장식에는 쓰지 않는다」

**D2 회색 단계**
- 무엇을 보나 — 회색이 몇 단계로 정해져 있는가
- 예 — 글자 회색이 여섯 가지
- 지시 — 「글자 회색 3단계, 선 회색 2단계만」

**D3 상태 색 의미 고정**
- 무엇을 보나 — 강조색과 성공 색이 비슷해 헷갈리지 않는가
- 예 — aikung은 올리브 그린 강조색과 성공 색이 비슷했습니다. 성공 색을 청록으로 바꾸고 체크 아이콘을 붙여 갈랐습니다
- 지시 — 「강조색과 성공 색이 비슷하면 색이나 아이콘으로 가른다」

**D4 밝은 강조색은 쓰는 자리를 나눠 색을 정한다**
- 무엇을 보나 — 강조색이 흰 바탕과 대비 4.5:1 미만(라임·노랑·민트처럼 밝은 색)인데, 흰 바탕 위 글자·밑줄·테두리에 그대로 쓰고 있는가
- 예 — 밝은 노랑 강조색으로 흰 바탕 위 링크 글자를 썼더니 읽히지 않음
- 지시 — 「강조색이 흰 바탕과 대비 4.5:1 미만이면 네 값으로 나눠 쓴다. ① 원래 색: 버튼·선택된 칩의 바탕(그 위 글자는 진한 색), 어두운 바탕 위 글자·아이콘 ② 진하게 한 색: 흰 바탕 위 선택 밑줄·테두리·포커스(3:1 이상) ③ 더 진한 색: 흰 바탕 위 강조 글자·링크(4.5:1 이상) ④ 아주 옅은 색: 선택된 칸 바탕. 네 값과 각 대비를 브리프 「4」 「색 — 강조」 행에 적는다」

## 7. E 부품

**E1 버튼 세 종류**
- 무엇을 보나 — 버튼이 주·보조·글자 세 종류이고 높이가 하나인가
- 예 — 화면마다 버튼 높이가 다름
- 지시 — 「버튼은 주·보조·글자 세 종류, 높이 하나」

**E2 상태까지 그리기**
- 무엇을 보나 — 부품의 다섯 상태가 그려져 있는가
- 예 — 평소 모양만 있고 비활성·포커스가 없음
- 지시 — 「평소·마우스 올림·누름·비활성·포커스 다섯 상태를 모두 그린다」

**E3 누르는 것과 보여 주기만 하는 것을 다르게 (필수)**
- 무엇을 보나 — 눌러지는 것과 정보만 보여 주는 것이 같은 모양인가
- 예 — aikung에서 참가자 수 상자와 추천 상자가 똑같이 생겨 사용자가 참가자 수를 눌러 보려 했습니다. 참가자 수를 회색 정보 줄 안의 사람 아이콘과 글자로 바꿔 갈랐습니다
- 지시 — 「보여 주기만 하는 정보는 상자로 만들지 말고 회색 정보 줄 안 아이콘과 글자로」
- **사용자 결정이 이긴다** — 이 항목은 기본값입니다. 사용자가 다르게 정하면(예: 보여 주기만 하는 숫자를 상자 모양으로 두기로 함) 그 결정을 따르고 브리프 「12. 화면 규칙」에 적습니다

**E4 아이콘 크기·선 굵기 통일**
- 무엇을 보나 — 아이콘 크기와 선 굵기가 같은가, 뜻이 애매한 아이콘에 글자가 붙어 있는가
- 예 — 20px·선 굵기 2로 통일
- 지시 — 「아이콘은 20px·선 굵기 2. 뜻이 애매하면 글자를 붙인다」

## 8. F 이미지 · G 상태 화면 · H 문구 · I 개성

**F1 이미지 비율 두 가지**
- 무엇을 보나 — 목록 이미지와 큰 이미지의 비율이 정해져 있는가
- 예 — 목록 1:1, 크게 16:9
- 지시 — 「이미지 비율은 목록 1:1, 크게 16:9 두 가지만」

**F3 작은 그림 위 표시는 작게, 모서리에**
- 무엇을 보나 — 작은 썸네일 위의 재생 표시·배지가 그림 안 글자를 가리는가
- 예 — 작은 썸네일 한가운데 큰 재생 표시가 올라가 썸네일 안 글자가 안 보임
- 지시 — 「작은 썸네일 위 재생 표시·배지는 20px 안팎으로 작게 모서리에 두고, 썸네일 안 글자를 가리지 않는다. 큰 그림에서는 키워도 된다」

**F2 자리 표시 모양 통일**
- 무엇을 보나 — 실제 사진이 없는 자리가 한 가지 모양인가, 사진을 지어내지 않았는가
- 예 — 옅은 단색 바탕 + 작은 아이콘 + 한 줄 설명
- 지시 — 「사진 자리는 옅은 단색 바탕, 작은 아이콘, 한 줄 설명으로 통일. 사진을 지어내지 않는다」

**G 상태 화면**
- 무엇을 보나 — 목록이 있는 화면마다 빈 상태와 로딩 화면이 있는가
- 예 — 데이터가 없을 때 빈 칸만 남음
- 지시 — 「목록이 있는 화면마다 빈 상태(다음 행동 버튼 하나)와 로딩(목록 모양 뼈대)을 그린다」

**H 문구**
- 무엇을 보나 — 버튼 글자가 무엇이 일어나는지 말하는가, 고정 문구가 글자 그대로인가
- 예 — 「확인」 대신 「일정 저장」
- 지시 — 「버튼은 무엇이 일어나는지 동사로 6자 안팎. 브리프 「문자 그대로」 표의 문구는 글자 그대로. 끝나면 화면 문구 검토 에이전트(ux-writing-reviewer)로 한 번 점검한다」

**I 개성**
- 무엇을 보나 — 로고 없이 봐도 그 서비스인 줄 아는 장면이 하나 있는가
- 예 — aikung은 마우스를 올리면 움직이는 챌린지 표지를 대표로 다듬었습니다
- 지시 — 「대표 장면 하나를 정해 그것만 더 다듬는다」

## 9. R 폰 화면으로 옮기기

**R1 칸 수가 줄어드는 순서**
- 예 — 1440 목록 + 오른쪽 칸 → 1024 오른쪽 칸을 목록 사이 띠로 → 390 한 칸
- 지시 — 「폭마다 칸 수가 줄어드는 순서를 규칙표에 적는다」

**R2 상단 메뉴가 접히는 폭**
- 무엇을 보나 — 메뉴가 햄버거로 접히는 폭, 끝까지 밖에 남는 버튼 하나
- 지시 — 「메뉴가 접히는 폭과, 접힌 뒤에도 밖에 남길 버튼 하나를 정한다」

**R3 목록 한 줄 덜어내기**
- 예 — 숫자 상자 둘 → 하나, 태그 둘 → 하나
- 지시 — 「폰에서는 목록 한 줄의 정보를 하나씩 덜어낸다」

**R4 옆 칸 버튼 → 화면 아래 고정 줄**
- 지시 — 「옆 칸에 있던 주 버튼은 폰에서 화면 아래 고정 줄로 옮긴다」

**R5 가로로 긴 표 → 한 줄씩 카드**
- 지시 — 「폰에서 가로로 긴 표는 한 행을 카드 하나로 바꾼다」

**R6 격자 열 수**
- 예 — 3 → 2 → 1
- 지시 — 「격자 열 수는 3 → 2 → 1로 줄인다」

**R7 제목만 한 단계 줄이기**
- 지시 — 「폰에서 제목만 한 단계 줄이고 본문은 그대로 둔다」

**R8 엄지 자리**
- 무엇을 보나 — 자주 누르는 버튼이 화면 아래쪽에 있고, 누르는 영역이 44px 이상인가
- 지시 — 「자주 누르는 버튼은 아래쪽에, 누르는 영역은 44px 이상으로」

**R9 가로로 밀리는 곳은 하나만**
- 예 — 거르기 칩 줄
- 지시 — 「가로로 밀어서 보는 곳은 화면당 하나만」

**R 규칙(폰 화면으로 옮기기)은 뷰포트 분기가 아니라 컨테이너 쿼리로 구현한다 — 뷰포트 분기는 화면 전체가 바뀌는 전환에만 쓴다.**

## 10. 지시서 한 장의 모양

개선을 맡기는 지시서는 아래 여섯 칸으로 씁니다. 핵심은 **규칙표를 먼저 만들게 하고, 그다음 그리게 하는 것**입니다.

| 칸 | 내용 |
|---|---|
| 화면 | 어느 화면을 고치나 |
| 1·2·3순위 | 이 화면에서 눈에 띄어야 할 순서 |
| 고칠 항목 코드 | 위 목록에서 고른 코드 (예: A1·A2·B1·C1·E3) |
| 바꾸지 말 것 | 기능 자리, 브리프 「문자 그대로」 고정 문구, 피할 것 |
| 비교안 개수 | A 지금 구조 다듬기, B 밀도를 낮춘 판 |
| 완료 보고 | 규칙표, 그리고 항목 코드별로 무엇을 왜 바꿨는지 |

예: 「화면: 챌린지 목록 / 1순위 챌린지 카드, 2순위 거르기 칩, 3순위 상단 메뉴 / 고칠 항목: A1·A2·A3·B1·C1·E3 / 바꾸지 말 것: 카드 안 참가 버튼 자리, 고정 문구 / 비교안: A, B 두 개를 새 아트보드로 / 완료 보고: 규칙표 + 코드별 변경 이유」

## 11. 규칙표는 어디로 가나

규칙표를 먼저 만들고 그리게 한 뒤, 확정된 값은 다음 자리로 갑니다.

- **브리프 「12. 화면 규칙」** — 규칙표 값이 여기로 갑니다. 사용자가 고른 판의 값만 적습니다.
- **코드에서** —
  - 글자 단계는 design-system의 **고정 글자 이름 대응표**로 갑니다.
  - 간격 허용 단계 · 격자 · 긴 글 폭은 프로젝트 `AGENTS.md` 「디자인 시스템 연결 정보」의 **적용 규칙 요약**으로 갑니다.
  - **새 토큰 층을 만들지 않습니다.** 간격은 Tailwind 단계 그대로 씁니다.
