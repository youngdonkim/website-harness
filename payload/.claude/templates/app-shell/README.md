# 셸 틀 (앱바·탭바)

모든 화면에 씌우는 셸(헤더 / 본문 / 하단)과, 화면이 폰 폭 앱바에 「뒤로·제목·동작」을 올리는 부품의 틀이다. 2-0 개발환경 준비가 셸을 매번 새로 짓지 않고 이 틀을 복사해 탭 배열만 채운다. 웹(Next.js) 스택 전용이다 — Expo는 네이티브 내비게이션이 앱바를 그리니 아래 「세 모양」 원칙만 같고 이 틀은 쓰지 않는다.

## 세 모양 — 폰 폭(768px 미만) 앱바

화면 종류는 기능·화면 목록(`mvp/feature-list.md`) 8절 「메뉴 구조」가 정한다.

| 화면 종류 | 앱바 (왼쪽 · 가운데 · 오른쪽) | 하단 탭바 | 본문 큰 제목 | 쓰는 부품 |
|---|---|---|---|---|
| 첫 탭(홈) | 로고 · (없음) · 알림·내 정보 | 보임 | 없음 | 아무것도 등록하지 않는다 |
| 나머지 탭 화면 | (빈 자리) · 탭 이름 · 알림·내 정보 | 보임 | 폰에선 숨김, 넓은 화면만 | `TabHeading` |
| 쌓이는 화면 (메뉴 → 상세) | 뒤로 · 화면 제목 · 동작 하나 | 보임 | 폰에선 숨김, 넓은 화면만 | `PageHeader` |
| 전체 화면 (로그인·온보딩) | 앱바 없음 또는 닫기만 | 숨김 | 화면 안 | `PageHeader appBar={false}` |
| 위에 뜨는 창 | (여는 화면의 앱바 그대로) | — | 창 안 | 창 부품의 제목 |

- 넓은 화면(768px 이상)은 모든 화면이 「로고 · 상단 메뉴 · 알림·내 정보」이고, 쌓이는 화면은 본문 맨 위에 뒤로 가기 줄을 둔다(브레드크럼은 두지 않는다).
- 브리프 「6. 주 사용 맥락」의 「첫 탭의 앱바」가 「모든 탭에 탭 이름」이면 첫 탭도 `TabHeading`을 쓴다. 「폰 메뉴 형태」가 하단 탭바가 아니면(햄버거·상단 탭) `shell-nav.tsx`의 `tabbar` 모양만 그 형태로 바꾸고 나머지는 그대로 쓴다.
- 전체 화면이 탭바를 숨기는 방법은 프로젝트가 정한다(그 화면을 셸 밖 레이아웃에 두는 등) — 틀은 모양만 제공한다.

## 파일

| 틀 파일 | 프로젝트에 넣는 자리 |
|---|---|
| `app-shell.tsx.template` | `src/components/app-shell.tsx` — 셸 + 앱바 등록(`useShellBar`) + 헤더 세 모양 |
| `shell-nav.tsx.template` | `src/components/shell-nav.tsx` — 탭 목록(`TABS`) 하나로 그리는 폰 하단 탭바·넓은 화면 상단 메뉴 |
| `shell-actions.tsx.template` | `src/components/shell-actions.tsx` — 헤더 오른쪽 알림·내 정보 단추 |
| `page-header.tsx.template` | `src/components/common/page-header.tsx` — 쌓이는 화면의 `PageHeader` + 탭 화면의 `TabHeading` |

## 넣는 차례

2-0 개발환경 준비의 디자인 시스템 첫 세팅 중 「셸」 차례에 한다 (`2-0-dev-setup.md` §2.5 4번).

1. **바닥이 있는지 본다** — 틀은 아래 이름을 쓴다. 없으면 셸 차례에서 먼저 만든다.
   - shadcn 부품 `button`·`sonner`(`npx shadcn add button sonner`).
   - 2층 이름: 좌우 여백 `px-screen-x`(`--spacing-screen-x`), 본문 최대 폭 `max-w-content`(`--container-content`), 글자 `text-h2`·`text-h4`·`text-b1`·`text-b2`, 둥글기 `rounded-control`, 셸 높이 `--shell-topbar-height`·`--shell-tabbar-height`, 하단 안전 영역 `--space-bottom-safe`.
   - 3층 셸 클래스 셋(`src/styles/3-components.css`):
     ```css
     .shell__top { height: var(--shell-topbar-height); }
     .shell__bottom { padding-bottom: var(--space-bottom-safe); } /* 홈 막대 자리는 하단 영역이 스스로 비운다 */
     .shell__tabbar { height: var(--shell-tabbar-height); }
     ```
   - 3층 `.press`(누르는 요소의 움직임)는 움직임을 정하는 단계가 만든다. 그 전엔 효과만 없고 깨지지 않는다.
2. **복사한다** — 위 표대로 네 파일을 복사하며 끝 이름의 `.template`을 뗀다.
3. **채운다** — 아래 「채울 자리」만 채운다. 그 밖의 줄은 고치지 않는다.
4. **루트 레이아웃에 씌운다** — `src/app/layout.tsx`의 `<body>` 안에서 `children`을 `<AppShell>`로 감싼다. 개발용 묶음 `(dev)`처럼 셸 없이 보여야 하는 곳은 프로젝트가 레이아웃을 갈라 둔다.
5. **연결 정보와 부품 목록에 적는다** — `AGENTS.md` 「디자인 규칙 검사 예외 줄」에 아래 네 줄이 있는지 보고(하네스 기본값으로 들어 있다), 네 파일을 `docs/components.md`에 등록한다.
6. **확인한다** — 타입 검사·린트·빌드. 화면에서 앱바가 맞게 바뀌는지는 사람이 목업 캔버스 폰 폭 틀에서 본다.

## 채울 자리

| 자리 | 파일 | 무엇으로 |
|---|---|---|
| `{{서비스 이름}}` | `app-shell.tsx` | 로고 자리 글자 — 로고가 정해지기 전까지 서비스 이름 |
| `TABS` 배열 (`{{첫 탭 이름}}`·`{{탭 이름}}`·`{{탭 주소}}`·`{{…아이콘}}`) | `shell-nav.tsx` | 탭마다 한 줄. 이름은 브리프 「3」 하단 탭 고정 문구 그대로, 첫 줄이 첫 탭(홈). 아이콘은 lucide 선형 아이콘 이름 |
| `{{쓰는 아이콘}}` | `shell-nav.tsx` | `TABS`에 쓴 아이콘 이름을 쉼표로 이어 import 줄에 |
| `{{알림 주소}}`·`{{내 정보 주소}}` | `shell-actions.tsx` | 그 화면의 주소. 그 화면이 없는 서비스면 그 단추를 뺀다 |

- **주소는 2-0이 지어 정하지 않는다** — 화면 목록이 아직 없으면 임시 주소를 두고, 2-1 첫 화면 에이전트가 주소 모음(`src/lib/paths.ts`의 `PATHS`)을 만들 때 `TABS`·`shell-actions.tsx`의 주소를 `PATHS["S-xx"]`로 바꾼다 (`2-1-mockup.md` §2.6.3 3번).
- 링크 단추는 `Button asChild` 안에 `Link`를 넣는 모양이다. 받은 `Button`이 다른 속성으로 링크를 받으면 연결 정보 「링크 버튼 쓰는 법」대로 그 줄만 바꾼다.

## 지키는 규칙

- **앱바 아래에 뒤로 가기 줄을 따로 두지 않는다** — 폰 폭 쌓이는 화면의 뒤로·제목·동작은 `PageHeader`가 셸 헤더에 올린다. 화면이 헤더를 숨기거나 화면마다 앱바를 새로 짜지 않는다.
- **화면은 `<h1>`을 직접 두지 않는다** — `PageHeader`(쌓이는 화면) 또는 `TabHeading`(탭 화면)이 h1을 맡는다. 폰 폭에서는 셸 헤더 제목이 h1이 되고 본문 제목은 넓은 화면에만 보여, 한 폭에 h1이 하나다. 예외는 둘이다 — 본문이 더 큰 제목을 따로 두는 상세 화면은 `PageHeader titleHidden`을 주고 그 큰 제목만 h1로 두고, 앱바에 제목이 없는 첫 탭(홈)·없는 주소 화면은 화면이 h1을 둔다. 3단계 디자인 규칙 검사 14번이 화면 폴더의 `<h1`을 세고, 이 둘은 걸려도 통과로 본다.
- **탭 화면·쌓이는 화면은 그 부품으로 시작한다** — 화면 맨 위 첫 요소가 `TabHeading` 또는 `PageHeader`다. 제목 글자는 화면 목록 6절의 「화면 이름」 그대로다(15자 안쪽, 길면 화면 목록에 적힌 앱바용 짧은 이름).
- **폭 분기는 틀의 네 줄뿐이다** — 뷰포트 접두어(`md:`)는 메뉴 전환 둘(`shell-nav.tsx`의 `VARIANT.top.frame`·`VARIANT.tabbar.frame`)과 헤더 전환 둘(`app-shell.tsx`의 `SHELL_WIDTH`)에만 있다. 이 네 줄은 `AGENTS.md` 「디자인 규칙 검사 예외 줄」에 등록한다. 화면 쪽 폭 대응은 컨테이너 쿼리로 한다. 화면에서 폭으로 앱바를 바꿔야 하면 `SHELL_WIDTH`를 가져다 쓴다.
- **셸 헤더에 대표 행동 버튼을 두지 않는다** — 화면의 주 버튼은 화면이 하나만 둔다.

## 있으면 쓰고 없으면 뺀다

- **화면 전환 움직임** — 주소가 바뀔 때 본문이 짧게 나타나는 움직임은 움직임을 정하는 단계가 붙인다. 붙일 때는 `app-shell.tsx`의 본문 틀 `div`를 `key={pathname}`을 단 부품(예: `screen-transition.tsx`)으로 바꾸고, 같은 클래스에 등장 움직임 클래스만 더한다. 없으면 틀 그대로 둔다.
- **안 읽은 알림 점** — 저장·조회 코드에 알림 수 함수가 생기면 `shell-actions.tsx`의 종 옆에 더한다(`shell-actions.tsx` 머리 주석).

## 깜빡임이 거슬리면

상세 주소로 바로 열면(새 탭·새로고침) 로고 앱바가 아주 잠깐 보였다가 「뒤로·제목」으로 바뀐다. 화면이 그려진 뒤에 앱바를 등록하기 때문이다. 앱 안에서 이동할 때는 생기지 않고 실서비스 빌드에서는 아주 짧아서, 기본은 그대로 둔다.

거슬리면 폴더 묶음(Next.js route group — 주소에는 안 나타나고 폴더만 묶는 이름)으로 모양을 서버에서 정한다.

1. 화면 폴더를 `src/app/(tabs)/`(탭 화면)·`src/app/(stack)/`(쌓이는 화면)로 나눈다.
2. 묶음마다 `layout.tsx`가 셸 헤더 모양(`tab`·`stack`)을 정해 그린다.
3. 화면은 제목과 동작만 등록한다.

대가는 모든 화면 폴더가 이 묶음을 따라야 한다는 것이다. 바꾸기로 했으면 설계 결정 기록(`mvp/adr.md`)에 한 줄 적는다.
