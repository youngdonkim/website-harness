## 1. 왜 바꾸나

- 지금은 같은 화면을 두 번 그린다: 2단계 목업 캔버스 → 3단계가 글(화면 인벤토리)로 다시 정리 → 4단계가 그 글을 보고 프로토타입 캔버스를 처음부터 다시 그린다.
- aikung 실측: 목업 캔버스 39장에 에이전트 약 25만 토큰, 첫 화면 디자인 개선 한 장(비교안 포함 6장)에 약 18만 토큰. 4단계 다시 그리기를 없애면 프로젝트마다 그 규모가 줄어든다.
- 그런데 2단계 그림이 최종 화면의 출발점이 되므로, 2단계에서 **전문가 수준으로 디자인을 개선하는 하위 단계**가 필요하다.

## 4. 2단계 — 목업

### 4.1 2-1 기능·화면 목록과 주요 화면

산출물 `feature-list.md`(제목 「기능·화면 목록」) — 지금 절 뒤에 옛 3단계 내용을 붙인다.

| 절 | 내용 |
|---|---|
| 1~4 | 기능 목록(역할별) · 범위 결정 · 정책 결정 · 라이트 기술 확인 · 실측으로 미룬 것 — 지금 그대로 |
| 5. 화면 목록 | ID · 화면 이름 · 역할 · 목적 · 들어오는 길 · 나가는 길 · MVP 포함 · **그리는 때**(2단계 / 3단계) · **아트보드 이름**(그렸으면) |
| 6. 상태 표 | 화면 × 정상·빈·로딩·오류·권한없음. 빈 칸 없이 `해당없음`까지 |
| 7. 메뉴 구조 | 폭별로 보이는 메뉴(상단 메뉴·햄버거·하단 탭), 같은 폭에 두 메뉴가 동시에 안 보이는 규정 |
| 8. 미룬 화면을 가리키는 버튼 | 옛 3단계 §4.3 그대로 |
| 9. 빠짐 점검 | 들어올 길 없는 화면 0, 못 나가는 화면 0, 일곱 갈래(상태 변형·분기·반대편 역할·진입점·계정·되돌리기·시스템) O/X, `만든다` 기능 → 화면 대조 |

- **그리는 범위** — 「그리는 때 = 2단계」: 플로우 표의 화면 + `만든다` 기능이 자리를 가져야 하는 화면. 첫 화면·상세·제출 등 핵심 화면은 폰판도.
- **「그리는 때 = 3단계」**: 빈·로딩·오류·권한없음 판, 설정·비밀번호 찾기 같은 계정 부속 화면, 삭제 확인 같은 되돌리기 화면.
- 일곱 갈래 훑기와 홈 유형 결정(옛 3단계 §2.2·§4.1 홈 규칙)은 이 문서로 옮긴다. 홈 결정의 기록 자리는 화면 목록 홈 행.
- 캔버스를 보며 다듬는 왕복(옛 §2.6)은 그대로. 나온 것은 기능·화면 → `feature-list.md`, 플로우 → `intent.md`, 문구·미감 → `design-brief.md`.
- 캔버스 배치: 흐름 줄마다 줄 제목 메모. 맨 아래에 새 줄을 쌓으면 찾기 어려우니, 나중에 더하는 화면은 **페이지**(캔버스의 `pages`)로 나눈다 — 「주요 화면」「디자인 개선」「3단계 추가 화면」.

### 4.2 2-2 전문가 수준 디자인 개선

문서 `2-2-mockup-design-upgrade.md`. 이름은 「다듬기」가 아니라 **「전문가 수준 디자인 개선」**으로 쓴다.

**들어오는 때** — 2-1에서 사용자가 기능·화면 목록을 확정한 뒤. 기능이 흔들리는 동안 개선하면 다시 해야 한다. 이 하위 단계는 건너뛰지 않는 것이 기본이다 — 2단계 그림이 최종 화면의 출발점이기 때문. 사용자가 그래도 건너뛰면 브리프 「12. 화면 규칙」에 `건너뜀 — 사유 (날짜)`를 남긴다.

**절차 — aikung에서 실제로 돌려 효과를 본 순서 그대로**

1. **점검 항목 설명** — 사용자에게 전문 디자이너가 보는 항목(A 시선과 위계 · B 글자 · C 간격과 정렬 · D 색 · E 부품 · F 이미지 · G 상태 화면 · H 문구 · I 개성, 폰 접기 R1~R9)을 화면 예와 함께 한 번 보여 주고, 적용할 항목을 고르게 한다(기본값: 전부).
2. **대상 화면** — 첫 화면 하나부터. 그다음 핵심 행동 화면 1~2장.
3. **규칙표 먼저** — 글자 단계 · 간격 단계 · 격자 · 색 쓰는 자리 · 버튼 종류와 다섯 상태(평소·마우스 올림·누름·비활성·포커스) · 아이콘 · 이미지 비율을 **규칙표 아트보드**로 먼저 만든다.
4. **비교안을 기존 판 옆에 새 아트보드로** — 데스크톱 A(지금 구조를 개선) · B(밀도를 낮춘 판), 폰판, 빈 화면, 로딩 화면. **기존 아트보드는 덮어쓰지 않는다** — 원래 판과 개선 판을 나란히 놓고 고르게 하는 것이 이 단계의 핵심이다. 새 판은 **새 공통 스타일(`-v2`)과 새 부품**으로 그려 다른 화면이 바뀌지 않게 한다. 캔버스의 「디자인 개선」 페이지에 놓는다.
5. **폰으로 접기** — 데스크톱을 먼저 확정하고 같은 화면을 R1~R9로 접는다. 1024·768은 그리지 않고 접히는 폭을 메모 한 장에.
6. **사용자 선택** — 링크와 함께 "A·B 중 어느 쪽인지, 섞어도 됨"과 **임시로 정한 것 목록**을 낸다. 사용자는 캔버스에서 보거나 댓글로 고친다(댓글로 받은 수정은 그 자리에서 고치고 브리프에 적는다 — aikung: 「분야별 색 빼기」「강조색 올리브 그린」「참가자 수에 사람 아이콘」).
7. **기록** — 고른 판의 규칙을 브리프 「12. 화면 규칙」에 `사용자 확정`으로. 색·부품 모양이 바뀌었으면 「4」, 피할 것은 「7」.
8. **퍼뜨리기** — 고른 판의 v2 공통 스타일·부품을 기본으로 바꿔(기존 부품 교체) 나머지 아트보드가 따라오게 하고, 깨진 화면만 손질한다. 화면을 통째로 다시 그리지 않는다.

**위임** — 3·4·5는 서브 에이전트 하나(opus — 디자인 판단이 많음). 지시서 템플릿은 aikung의 `mvp/mockup/polish-prompt.md`를 일반화해 이 문서 §4에 싣는다: `<direction>`(새로 만들 아트보드 표·우선순위·항목 전체) · `<constraints>`(브리프 읽는 법·피할 것·기능 자리 그대로·접근성) · `<done-when>`(규칙표, 항목 코드별 바꾼 것, 덜어낸 정보, 임시로 정한 것, 링크).

**점검 항목의 정본** — `design-system/references/visual-polish.md`(새 파일). 2-2 문서는 "메인이 이 문서를 읽고 대상 화면에 닿는 항목을 지시서에 걸러 넣는다"고만 쓴다. 항목 목록은 §9.2.

## 5. 3단계 — 프런트엔드

옛 `4-frontend-build.md`를 `3-frontend-build.md`로. 바뀌는 곳:

- **§1 입력** — `information-architecture.md` → `feature-list.md` 5~9절(완전성) + **2단계 캔버스(원본)** + `intent.md` + `design-brief.md`(문구·미감·「12. 화면 규칙」). 「2단계 캔버스는 입력이 아니다」 문단 삭제.
- **§2.2 캔버스** — "새 캔버스를 만든다" → "**2단계 캔버스에 「그리는 때 = 3단계」인 화면만 추가한다**". 「3단계 추가 화면」 페이지에. 이미 있는 아트보드는 다시 만들지 않는다. 시작 전 클라우드 최신본을 읽는다(사람이 고쳤을 수 있음).
- **완전성 확인** — 화면 목록의 `MVP 포함 = O` 화면과 상태 표의 `O` 칸이 전부 아트보드로 있는지, 화면 목록의 「아트보드 이름」 열을 채우며 대조.
- **§2.5 마이그레이션** — 원본이 2단계 캔버스라는 점만 다르다. 브리프 「12. 화면 규칙」을 디자인 토큰 1층으로 옮긴다(글자 단계 → 글자 토큰, 간격 단계 → 간격 토큰). 빠짐 검사 기준은 화면 목록 ID.
- **얼리는 때** — 3단계에 들어오는 순간 `intent.md`·`feature-list.md`·`design-brief.md`가 기록으로 얼려진다(「8. 모션」 행만 배포 확인까지 열림 — 지금과 같음).
- `mvp/prototype/` 폴더와 그 `.gitignore` 줄 삭제.

## 6. 캔버스는 어디에 있고 무엇을 커밋하나

- **원본은 클라우드다** — 캔버스는 claude.ai 아티팩트로, 게시한 계정(이 프로젝트는 회사 계정)에 저장된다. 사용자가 브라우저에서 고친 것은 클라우드에만 들어간다.
- **로컬 폴더(`mvp/mockup/project/`)는 게시용 사본이다** — 에이전트가 파일을 써서 올리는 출발점일 뿐, 사람이 브라우저에서 고친 뒤에는 클라우드보다 낡는다. 그래서 커밋하면 낡은 사본이 정본처럼 보인다 → **계속 git에서 뺀다.**
- **어긋남을 막는 장치는 이미 있다** — 아티팩트 게시는 최신 버전을 읽지 않으면 거절된다. 규칙으로 못 박는다: "캔버스를 고치기 전에 클라우드 최신본을 읽는다(주소만으로 한 번 읽고, 고칠 파일을 경로로 읽는다)". 이 줄을 모든 캔버스 위임 지시서에 넣는다 — aikung에서 서브 에이전트가 이걸 몰라 두 번 거절당했다.
- **커밋하는 것** — 캔버스 링크(`feature-list.md` 머리 한 줄)와 지시 파일(`mvp/mockup/design-prompt.md`·`polish-prompt.md` 같은 것). `.gitignore`를 `mvp/mockup/project/`와 `mvp/mockup/_progress.md`만 빼도록 좁힌다.
- **세션이 바뀌어도 이어 쓸 수 있다** — 링크만 있으면 어느 세션·에이전트든 클라우드에서 읽어 이어 쓴다. 계정이 다르면 못 연다 → 계정 확인(`docs/account-check.md`) 대상에 캔버스 소유 계정도 넣는다.
